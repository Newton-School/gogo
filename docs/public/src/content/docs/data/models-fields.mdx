title: Models and Fields

---

Model metadata is the source of truth for fields, validation, migrations, admin,
serializers, permissions, and ORM query compilation.

## Public packages

| Package | Purpose |
| --- | --- |
| `models` | model metadata, registry, lifecycle state, indexes, constraints, inheritance, permissions, and validation hooks |
| `models/fields` | Django-style field constructors and field-level conversion and validation |
| `models/constraints` | index and constraint metadata helpers |
| `contrib/postgres/vector` | PostgreSQL pgvector field metadata and HNSW/IVFFlat index helpers |
| `models/hooks` | model lifecycle hooks |
| `models/validation` | structured validation errors |

## Example metadata

```go
package blog

import "github.com/cybersaksham/gogo/models"

func PostMetadata() models.Metadata {
	return models.Metadata{
		AppLabel:  "blog",
		ModelName: "Post",
		TableName: "blog_post",
		Fields: []models.FieldMeta{
			{Name: "id", Column: "id", Kind: "uuid", PrimaryKey: true, DBDefault: models.DefaultSQL("gen_random_uuid()")},
			{Name: "author", Column: "author_id", Kind: "uuid", RelationTarget: "auth.User"},
			{Name: "title", Column: "title", Kind: "text"},
		},
	}
}
```

Add explicit field names, column names, defaults, null and blank behavior,
choices, validators, indexes, constraints, and custom permissions when those
rules affect database, admin, API, or auth behavior.

Metadata validation rejects duplicate field names or columns, declared fields
without a primary key, duplicate index or constraint names, and duplicate custom
permission codenames. After registering all models, use
`models.Registry.ValidateRelations` to catch unknown relation targets.

Set `Managed` to false for existing tables that Gogo should expose through
ORM/admin/API metadata without including them in migration state.

Use `fields.NewCustomField` or explicit `models.FieldMeta.ColumnTypes` for
database-specific column types. Database-generated primary keys should declare
`PrimaryKey: true` and a `DBDefault`; Gogo create paths omit those primary keys
and read the generated value back on dialects that support `RETURNING`.

For non-bigint relation columns, set `RelationConfig.ColumnTypes` or explicit
relation field kinds. When a relation kind is omitted, migration state infers it
from the registered target model primary key. The `contrib/postgres/vector`
package provides metadata helpers for pgvector fields and HNSW/IVFFlat indexes.

Managed relation fields also generate expected foreign-key constraint metadata.
Use `TargetFieldName` when a relation references a non-primary-key target field.
`protect` maps to SQL `RESTRICT`; `set_value` maps to `NO ACTION` because
arbitrary value assignment is handled by runtime delete behavior, not a database
foreign-key action.

Use `models.Unique` for simple table-level uniqueness. Use
`models.NewUniqueIndex` for expression, partial, include, opclass, or
method-specific unique indexes:

```go
models.NewUniqueIndex("uniq_blog_post_lower_title").
	WithExpressions("LOWER(title)").
	WithCondition("deleted_at IS NULL")
```

Advanced unique constraints with expressions, predicates, include columns, or
opclasses are converted to unique index state during migration generation.
