# Scoped relation aggregation

`Annotate` adds typed aggregate results to `State().Annotations`; `Aggregate`
returns scalar results. Aggregate paths resolve foreign keys, reverse query
names, and many-to-many relations through the frozen model registry. Collection
joins do not populate `State().Related` or add child identity to model grouping.

```go
query := orm.For(store, productFactory).WithScope(resourceScope).Annotate(
    map[string]orm.ResultExpression{
        "tags_count": orm.Typed(orm.Count(orm.F("tags__id")), models.BigIntegerField("out")),
    },
)
rows, err := query.Filter(orm.Q("tags_count__gt", 0)).All(ctx)
```

| Boundary | Current behavior |
| --- | --- |
| Root, target and explicit intermediary | Each receives its own `QueryScope`; failure or cancellation prevents SQL execution. |
| Automatic intermediary | Only a bridge generated by `Registry.Freeze` can omit application scope. Both application endpoints remain scoped. |
| Many-to-many target hidden | The bridge and visible target form an inner join **inside** the parent's outer join. Hidden links cannot multiply parent counts or sums. |
| No visible targets | Parent survives with `Count(target)=0`; normal aggregate null/default rules apply. |
| Multiple visible collections | Ordinary SQL row multiplication applies. Use `DistinctAggregate(Count(...))` for distinct identities when appropriate. |
| Scalar endpoint | Single effective primary key or declared unconditionally unique stored scalar key, including explicit non-primary through targets. |
| Reverse traversal | Uses `RelatedQueryName`, then `RelatedName`, then the lower-case source model name; instance accessor names remain separate. |
| Automatic self-symmetric relation | Uses the stored forward/mirror links; each endpoint is scoped and a self-link counts once. |
| Scoped explicit self-symmetric relation | Returns `UnsupportedFeature` before SQL until paired intermediary authorization is implemented. Unscoped explicit symmetry uses stored links. |
| Backend | Requires the public `grouped_relation_joins` capability and the matching `FeatureDialect` capability. PostgreSQL advertises both. |
| Bounds and visibility | At most eight relation path segments and 64 resolved relation joins; bridge aliases never become public field paths or hydrated objects. |

This is a bounded implementation, not complete ORM expression parity. A plain
row expression does not automatically create a collection join. Custom/derived
or composite relation endpoint types are rejected in this aggregate path.
