# Gogo v1.0.0-alpha.1

First alpha of the rebuilt, modular Gogo framework. This is **not** a stable
1.0 release or a declaration of complete Django/Celery parity. API and database
compatibility may change during the alpha series.

## Install exact versions

Requires Go 1.26.8 or newer. Install the generator:

```sh
go install github.com/Newton-School/gogo/cmd/gogo@v1.0.0-alpha.1
gogo version
gogo startproject storefront --module example.com/storefront
```

The generated project pins Core and PostgreSQL to this release. Optional
modules are installed and registered explicitly; installation alone does not
activate Admin, Async, Redis, or any background process.

| Module | Git tag | Requires Gogo modules |
| --- | --- | --- |
| `github.com/Newton-School/gogo` | `v1.0.0-alpha.1` | None |
| `github.com/Newton-School/gogo/admin` | `admin/v1.0.0-alpha.1` | Core |
| `github.com/Newton-School/gogo/async` | `async/v1.0.0-alpha.1` | Core |
| `github.com/Newton-School/gogo/connectors/postgres` | `connectors/postgres/v1.0.0-alpha.1` | Core |
| `github.com/Newton-School/gogo/connectors/redis` | `connectors/redis/v1.0.0-alpha.1` | Core |
| `github.com/Newton-School/gogo/async/redis` | `async/redis/v1.0.0-alpha.1` | Core, Async, Redis connector |

All module dependency versions are `v1.0.0-alpha.1`; tag prefixes identify
submodule directories, not versions to pass to `go get`. Pin the prerelease
explicitly: `@latest` can still select the older stable `v0.11.0` line.

```sh
go get github.com/Newton-School/gogo/admin@v1.0.0-alpha.1
go get github.com/Newton-School/gogo/async@v1.0.0-alpha.1
go get github.com/Newton-School/gogo/connectors/redis@v1.0.0-alpha.1
go get github.com/Newton-School/gogo/async/redis@v1.0.0-alpha.1
```

## Included implementation

- Explicit app registry, typed configuration and central management commands;
  project/app scaffolding, model generation, read-only descriptor checks,
  migrations and development reload on Linux/macOS.
- Model descriptors and validation, typed ORM query references, transactions,
  relations, migration operations and PostgreSQL execution.
- Routing, HTTP responses, forms/widgets, templates, API resources, security,
  authentication/session services, storage, cache, mail, signals and contrib
  packages. Configuration and integration remain explicit.
- Independently installable Admin with model registration, forms, list views,
  permissions, actions, inlines, audit history and staff documentation.
- Independently installable Async with workers, retries, result storage,
  workflow primitives, scheduling and Redis adapters.
- Explicit bounded operation telemetry. No automatic whole-stack tracing is
  implied by importing the package.

## Migration from v0.x

This repository was rebuilt after v0.11.0. The former flat import tree and
queue API are not source-compatible with the new `core/`, `admin/`, `async/`
and connector modules. There is no automatic data/migration-history converter
from the former implementation. Start a separate client project, port models
and configuration explicitly, and validate data migration and rollback against
a backup before changing an existing system. Do not point this alpha's
migrations at an old production schema as an upgrade shortcut.

## Alpha boundaries

The framework remains incomplete. Constructor
or catalog presence does not prove every ORM, form, API, Admin and backend
combination supports that item. Unsupported combinations must fail explicitly;
they must not be treated as implemented behavior.

Full API/account flows, field/backend combinations, advanced ORM behavior,
Admin combinations and visual/accessibility coverage, nested workflow recovery,
GIS, direct cloud uploads, production deployment/restore drills, and complete
operational instrumentation are not claimed complete. PostgreSQL and Redis are
the initial connectors; no Python ABI or Celery wire compatibility is promised.
Task delivery does not imply exactly-once external side effects.

See the [compatibility guide](../docs/guides/compatibility.md) for support boundaries and
remaining work. The [showcase](https://github.com/Newton-School/gogo/tree/master/examples/showcase) is a separate
pinned consumer added after the immutable release commit. Its
[coverage map](https://github.com/Newton-School/gogo/blob/master/examples/showcase/COVERAGE.md) distinguishes executable
demonstrations, descriptor-only support and limitations; it is not bundled in
the release tag or required by the framework modules.

## Release checks

The maintainer gate includes workspace race tests, Admin JavaScript tests,
real PostgreSQL/Redis integration tests, independent-module tests with workspace
overrides disabled, generated-consumer compilation, vet/build, dependency
vulnerability scanning and license inventory. Results are dated evidence, not
a guarantee that software is free of defects.
